## 1. 全体像

自分の講座を販売するための動画講座プラットフォームです。動画はYouTubeの埋め込みで配信します。

進め方は「まず教材どおりに完成させ、その後で実際に販売する」です。そのため、最初のMVP（最小限の完成形）には決済を入れず、視聴と進捗の流れを先に完成させます。

本に例えると、次のような構成です。

| 例え | このシステム | 内容 |
|---|---|---|
| 1冊の本 | コース | 販売・受講の単位 |
| 章 | セクション | レッスンをまとめる単位 |
| 節 | レッスン | YouTube動画1本 |
| 読み終えた節の印 | 進捗 | レッスンごとの完了記録 |
| 書店の棚に並べる前の本 | 下書きのコース | 受講者には見えない |

## 2. 決定事項の一覧

| 項目 | 決定内容 | 理由・補足 |
|---|---|---|
| 目的 | 自分の講座を販売する | 講師は自分だけ |
| 進め方 | 教材どおりに完成させてから販売する | DMMの教材を見ながら作る |
| 決済 | MVPには含めない | 販売の準備段階で追加する |
| 視聴できる人 | ログインした人は全講座を視聴できる | MVPの間だけの扱い |
| ログイン方法 | Googleログインのみ | パスワード関連の機能が不要 |
| 管理者 | 自分だけ | 環境変数 `ADMIN_EMAIL` と比較して判定する |
| 講座の構成 | コース＞セクション＞レッスン | 3階層 |
| レッスンの中身 | YouTube動画のみ | 本文や添付ファイルは持たない |
| 動画の登録方法 | YouTubeのURLを貼り付ける | サーバー側で動画IDを取り出して保存する。対応形式は `youtube.com/watch?v=ID` と `youtu.be/ID`。形式が正しくないURLはエラーにする |
| 動画の公開設定 | すべて限定公開 | YouTube側で設定し、埋め込みも許可する。URLを知っている人は視聴できる |
| 再生できない場合の表示 | YouTubeプレーヤーの表示に任せる | 独自の案内は作らない |
| 進捗の記録 | 自動の完了と「完了」ボタンの併用 | 再生位置の記録はしない |
| 完了の取り消し | できる | 「完了」ボタンを押し直すと未完了に戻る |
| 視聴順 | 自由 | 順番のロックはしない |
| ログイン前に見せる範囲 | コース一覧・詳細は公開 | レッスン視聴はログイン必須 |
| 公開状態 | コース単位で下書きと公開を切り替える | セクションとレッスンに状態は持たせない |
| 公開の条件 | レッスンが1本以上あること | 公開に切り替えるAPIでサーバー側が確認する。サムネイルの指定は条件にしない |
| 削除 | コース・セクション・レッスンのすべてを削除できる | 確認ダイアログあり。元に戻せない |
| レッスンが0本になる削除 | 公開中のコースでは止める | 先に下書きへ戻すよう案内する |
| 並び替え | 「上へ」「下へ」ボタン | セクションとレッスンが対象 |
| サムネイル | `public` に置き、Gitに含めてデプロイする | アップロード機能は作らない |
| サムネイルの指定方法 | 画像の場所を入力し、プレビューで確認する | 一覧から選ぶ機能は作らない |
| デプロイ先 | Vercel | |

## 3. 技術構成（決定）

| 役割 | 使うもの |
|---|---|
| フロントエンド | Next.js |
| バックエンド | Next.jsのAPI |
| データベース | Turso |

## 4. MVPの機能

### 4.1 受講者向け

| 機能 | ログイン | 内容 |
|---|---|---|
| コース一覧 | 不要 | 公開中のコースを表示する |
| コース詳細 | 不要 | セクションとレッスンの名前を表示する |
| レッスン視聴 | 必須 | YouTube動画を再生する |
| 進捗の記録 | 必須 | レッスンの完了を記録する |
| 進捗の表示 | 必須 | 「10レッスン中3レッスン完了」のように表示する |

### 4.2 管理者向け

| 機能 | 内容 |
|---|---|
| コースの管理 | 作成・保存・修正・削除、下書きと公開の切り替え |
| セクションの管理 | 作成・保存・修正・削除、並び替え |
| レッスンの管理 | 作成・保存・修正・削除、並び替え |
| サムネイルの指定 | `public` に置いた画像の場所をコースに結び付ける |

### 4.3 MVPに含めないもの

- 決済、購入履歴、購入者だけが視聴できる仕組み
- 複数の講師の参加、売上の分配
- メールとパスワードでのログイン
- サムネイルのアップロード
- 再生位置の記録、続きからの再開
- レッスンの順番のロック
- 削除したデータの復元（ゴミ箱）
- 別のセクションへのレッスンの移動
- レッスンの本文や添付ファイル

## 5. 動作のルール

### 5.1 ログインと管理者の判定

- ログインはBetter AuthのGoogleログインで行います。
- 環境変数 `ADMIN_EMAIL` と、Googleで確認済みのメールアドレスが一致する人を管理者とします。
- 管理用の画面とAPIの両方で、**サーバー側で**管理者かどうかを確認します。画面を隠すだけでは保護になりません。
- 管理者を変更するときは、環境変数を更新して再デプロイします。
- 未ログインで管理画面を開くと `/login` へ移動します。管理者以外のログインユーザーには「ページが見つからない」表示を返し、管理画面の存在を隠します。
- ログイン後は `/` へ戻ります。

### 5.2 公開範囲

- 受講者向けの画面とAPIでは `published` のコースだけを扱います。
- 管理画面では `draft` と `published` の両方を表示します。
- 公開中のコースにレッスンを追加すると、保存した時点で受講者に見えます。
- レッスンが1本以上あるコースだけを公開できます。公開に切り替えるAPIでサーバー側が確認します。
- サムネイルが未指定のコースには、代わりの画像を表示します。
- ログイン前のページやAPIのレスポンスに、動画ID（`youtubeVideoId`）を含めません。画面に表示していなくても、ブラウザから読み取れる場合があるためです。

### 5.3 進捗

- 動画が最後まで再生されたら、自動で完了にします。再生状態はYouTube IFrame Player APIで受け取ります。
- 受講者は「完了」ボタンでも完了にできます。
- 「完了」ボタンを押し直すと未完了に戻ります。`lesson_progress` の該当する行を削除するため、過去の完了日時は残りません。
- 未完了に戻した後でも、動画を最後まで再生すると再び完了になります。
- 早送りやボタン操作でも完了にできるため、「確実に視聴したこと」の証明にはなりません。

### 5.4 削除

- コースを消すと、配下のセクション、レッスン、進捗も一緒に消えます。
- レッスンを消すと、全体のレッスン数と進捗の表示も変わります。
- 公開中のコースでレッスンが0本になる削除は止め、先に下書きへ戻すよう案内します。レッスンの削除APIとセクションの削除APIの両方で、サーバー側が確認します。
- 削除ボタンは保存ボタンから離し、確認ダイアログを挟みます。
- 通信中はボタンを押せないようにして、二重送信を防ぎます。
- 実際に販売を始める前に、購入履歴や受講者の進捗を消してよいか見直します。

### 5.5 サムネイル

- 画像を `public/thumbnails/` に置いてGitに含め、デプロイします（例: `/thumbnails/course-1.png`）。
- DBには画像そのものではなく、画像の場所を保存します。
- 画像を置いてデプロイした後、管理画面で場所を入力し、プレビューで確認して保存します。
- 本番環境の画像を変えるには再デプロイが必要です。

Vercelでは実行中に保存したファイルが残り続けません。また、Next.jsの `public` フォルダで本番環境に配信されるのは、ビルド時点にあったファイルだけです。この2点から、この運用を選びました。

## 6. データ設計（実装済み）

Better Authが使うテーブルに加えて、次のテーブルがあります。定義の正本は `src/db/course-schema.ts` です。説明とサムネイルは未入力でも保存できます。`status` の選択肢はTypeScript側で管理し、DB側では制限していません。

```text
courses（コース）
  id
  title              タイトル
  description        説明
  thumbnail_path     サムネイルの場所（例: /thumbnails/course-1.png）
  status             draft または published
  created_at
  updated_at
    │ 1対多
    ▼
sections（セクション）
  id
  course_id          どのコースのものか（コース削除時に一緒に削除）
  title              タイトル
  position           並び順
    │ 1対多
    ▼
lessons（レッスン）
  id
  section_id         どのセクションのものか（セクション削除時に一緒に削除）
  title              タイトル
  youtube_video_id   YouTubeの動画ID
  position           並び順
    │ 1対多
    ▼
lesson_progress（進捗）
  user_id            誰の記録か（ユーザー削除時に一緒に削除）
  lesson_id          どのレッスンか（レッスン削除時に一緒に削除）
  completed_at       完了した日時
  ※ user_id と lesson_id の組み合わせは重複させない
```

## 7. 画面とURL（案）

| 画面 | URL | ログイン |
|---|---|---|
| ログイン | `/login` | 不要 |
| コース一覧 | `/` | 不要 |
| コース詳細 | `/courses/[courseId]` | 不要 |
| レッスン視聴 | `/courses/[courseId]/lessons/[lessonId]` | 必須 |
| 管理: コース一覧 | `/admin` | 管理者のみ |
| 管理: コース編集 | `/admin/courses/[courseId]` | 管理者のみ |

## 7.1 管理用API

すべて管理者専用です。処理の窓口はRoute Handlerで、判定や保存はサービス層に置きます。

| 操作 | メソッドとURL |
|---|---|
| コース一覧 | `GET /api/admin/courses` |
| コース作成 | `POST /api/admin/courses` |
| コース取得（セクション、レッスンを含む） | `GET /api/admin/courses/[courseId]` |
| コース修正 | `PATCH /api/admin/courses/[courseId]` |
| セクション作成 | `POST /api/admin/courses/[courseId]/sections` |
| セクション修正 | `PATCH /api/admin/sections/[sectionId]` |
| レッスン作成 | `POST /api/admin/sections/[sectionId]/lessons` |
| レッスン修正 | `PATCH /api/admin/lessons/[lessonId]` |
| コースの公開 | `POST /api/admin/courses/[courseId]/publish` |
| コースを下書きに戻す | `POST /api/admin/courses/[courseId]/unpublish` |
| コース削除 | `DELETE /api/admin/courses/[courseId]` |
| セクション削除 | `DELETE /api/admin/sections/[sectionId]` |
| レッスン削除 | `DELETE /api/admin/lessons/[lessonId]` |
| セクションの並び替え | `POST /api/admin/sections/[sectionId]/move` |
| レッスンの並び替え | `POST /api/admin/lessons/[lessonId]/move` |

並び替えの本文は `{ "direction": "up" }` または `{ "direction": "down" }` です。

新しいセクションとレッスンは、同じ親の中で最後に追加します。別のセクションへのレッスンの移動はできません。

公開状態はコース修正では変更できません。公開と下書きへの変更は、専用のAPIで公開の条件を確認します。

エラーは、すべて次の形式で返します。

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "画面に表示できる説明" } }
```

| ステータス | `code` | 意味 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 入力が正しくない |
| 401 | `UNAUTHORIZED` | 未ログイン |
| 403 | `FORBIDDEN` | 管理者以外 |
| 404 | `NOT_FOUND` | 対象が存在しない |
| 409 | `CONFLICT` | 業務ルールにより実行できない（公開の条件を満たさないなど） |
| 500 | `INTERNAL_ERROR` | サーバー側の想定外のエラー |

## 10. 実際に販売を始める前の確認事項

MVPの完成後に対応します。

| 項目 | 確認すること |
|---|---|
| 決済 | 決済サービスの導入、購入履歴、購入者だけが視聴できる仕組み |
| 動画の保護 | ログイン後の画面では動画IDが見える。URLが広まると未購入の人も視聴できる可能性を、どこまで許容するか |

| ログイン方法 | Googleアカウントがない人も受講者にするか |
| データの削除 | 購入履歴や進捗があるコースを消してよいか |
| 法律・規約 | 利用規約、プライバシーポリシー、特定商取引法に基づく表記などを確認する |
